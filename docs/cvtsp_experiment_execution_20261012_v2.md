# CVTSP 三组从头训练与诊断执行顺序

日期：2026-10-12。状态：三组从头训练各20轮已全部完成，最后一组于2026-10-13 00:08（UTC+8）结束；完成审计通过。每组实际训练40万实例，未自动继续第21轮。

## 1. 已确认的实验设计

三组同时从头训练，各观察前20个epoch；学习率和move预算均按100个epoch总计划调度。旧Epoch20/100/365不作为本实验输入。网络学习诊断直接嵌入三组新训练，不从历史checkpoint续训。

| 组别 | 局部搜索算子 | 初始化 | 观察长度 |
|---|---|---|---|
| A | swap-only | 新随机初始化 | 20 epoch |
| B | 2-opt-only | 相同新初始化 | 20 epoch |
| C | swap＋2-opt | 相同新初始化 | 20 epoch |

C组保留当前合用方式：扫描两种邻域，按同一接受规则选最优move；不是每步随机各选50%，也不要求两种算子的接受次数相等。三组Reference/Predictor初始状态相同，Reference复制新Target，replay初始为空，不载入任何旧训练状态。

### 公共设置

| 项目 | 设置 |
|---|---|
| 训练总计划/本阶段 | 100 epoch / 先运行20 epoch |
| 每epoch实例 | 20000；三组各40万，本阶段共120万 |
| Batch/J/POMO | 64 / 20–100 / J |
| Reference候选 | 200，原去重与采样规则 |
| Anchor | 原Predictor筛选、Gurobi精算和严格上界构造 |
| Top-K | 30，质量20＋质量受限多样性10，前60/5%门槛 |
| Move上限 | 从30到10，按100轮线性减少，三组完全相同 |
| RL | 标准化密集POMO＋有界精确Expert辅助，原自适应权重 |
| IL/Replay | IL5遍，改进Expert权重5；replay30%，容量50000 |
| Near-miss | 保留原1%–5%自适应规则，不因组别改变 |
| 学习率 | 初始1e-4、最小1e-5；余弦总长100、warmup1 epoch |
| 固定验证 | 已冻结2000例，原单greedy精算、Reference门槛与best规则 |
| 人工测试 | 已冻结500例，保留给冻结配置后的正式测试 |

每条搜索链允许的最大接受步数定义为：

`M(e) = round(30 - 20 * (e - 1) / 99)`，e=1…100，整数限制在10…30。

第1轮30，第20轮约26，第100轮10。找不到改善move仍提前结束。实现时固定取整规则并保存当轮实际M(e)。即使本次只运行20轮，也不能把两个scheduler的总长度缩到20。实际学习率与move上限逐epoch落盘。

现有e500 profile会覆盖同名算法设置；实现时需要显式处理新实验参数优先级，检查解析配置中min-LR=1e-5、对应move_types和动态M(e)均真实生效。旧E500配置保持可复现，不将旧实验描述改写为新配置。

## 2. 第一步：实现诊断记录并验证不会改变训练

### 局部搜索必记字段

- 每J/起点类型的搜索链总数、接受步数均值与分位数、步数直方图、终止原因、当前上限命中率。
- 超过10步、20步的路线比例，及第10步之后的累计上界下降。
- swap/2-opt分别的候选评估数、接受数、累计接受上界下降。
- 最终被选为Expert候选的搜索链：起点类别、步数、算子顺序、初始/最终上界、精确值和Expert来源；回退Anchor和near-miss分别标记。
- Anchor到Expert的真实改善、改善实例占比、Gurobi调用数。
- 搜索墙钟耗时、worker累计耗时；同时记录CPU/GPU资源分配，不能把累计worker时间当作训练墙钟时间。

### 网络学习必记字段

- RL与IL逐更新的裁剪前/后梯度范数，阶段净参数变化量、更新次数、耗时。
- 密集RL/精确辅助loss、辅助权重、优势分布、Target相对Expert的真实胜率和差距。
- IL token accuracy、改进样本数量、实际replay比例和池大小。
- 诊断batch记录RL分项梯度强度和方向相似度；额外梯度计算不得执行优化器更新或改变训练梯度。

每epoch保存汇总；每J保留少量逐实例/逐链明细。记录阶段性检查点或在独立评价环境直接诊断。评价用独立随机数，不消耗训练RNG、不更新Reference/replay，不污染模型训练模式或rollout缓存。

实现后先做语法和相关单元测试，固定输入下确认开启/关闭日志的路线、接受move及参数更新一致；验证单算子和双算子模式、M(1)=30/M(20)=26/M(100)=10，以及100轮LR状态可保存恢复。检查额外诊断耗时。

## 3. 第二步：准备独立诊断集与一致训练数据流

- 新建固定诊断100例，J20/40/60/80/100各20，保存seed、校验和和指纹；与已保存验证/测试数据查重。全精确POMO诊断使用其中预先固定的50例，每J10例，不能看结果后选样本。
- 正式测试500和Real529不用于这一轮选参数。现有固定验证2000保持原用途。
- 三组同一初始化seed，并预生成或隔离训练实例的RNG，使三组每个batch的J和实例一致；记录指纹校验一致性。不能仅凭相同全局seed认定数据流相同。
- 候选路线和Expert随各组网络成长自然分化，不强制后续Reference/Predictor/replay保持相同；差异是训练效果的一部分。

## 4. 第三步：三组同时运行前20轮

启动前检查GPU剩余显存、CPU核心、当前任务、Gurobi和CUDA环境，统一每组资源与线程配置。原128worker是单作业计划；不得直接默认为三组各128合计384而导致超额争用。确定并记录每组及总worker预算；如果无法支持三组并行，先说明实测限制，再调整排队方式。

本机实测：RTX4090 24GB、32 CPU线程；每组8worker，总计24。J=100/batch64每组显存峰值约9GB，三组无约束并发会OOM。保留全部算法参数和batch64，三组tmux常驻，大显存阶段最多两组并发；每次退出释放空闲CUDA缓存并给等待组调度机会。GPU等待耗时单独记录，不能把资源等待误认作算法变慢。

分别用独立tmux会话、输出目录和日志运行，不覆盖旧实验。入口将run epochs设20，scheduler/move horizon保持100；或者明确限制100轮计划只执行到20，避免自动跑完整100轮。每epoch保存checkpoint，所有训练状态及动态move调度可以恢复。

仅汇报启动成功、异常、阶段完成或需要决策；不持续推送日志。

## 5. 第四步：网络学习诊断与三组同步进行

不新增旧模型续训实验；首先只观察，不同时改变IL、replay或reward。

| 时点 | 评价内容 |
|---|---|
| Epoch1/5/10/20开始、RL后、IL后 | 固定诊断100例，单greedy＋Gurobi精确makespan，分J汇总 |
| Epoch5/20的RL后、IL后 | 固定诊断50例，greedy完整POMO、无增强、精算全部不同路线取最优 |
| Epoch1/5/10/20结束 | 固定诊断50例，按训练采样方式生成Target POMO；复现上界选路并精算全部不同候选 |

RL后与IL后的比较保持实例和解码方式一致；greedy完整POMO评价与训练采样POMO诊断分开统计。后者记录：上界选中路线真实排名、精确选择regret、上界松弛、混合与全精确优势符号一致率。精确排序参考只是本次候选中最优，不是全局最优。求解非最优或失败单独报告。

这些诊断不得额外产生训练标签或回灌replay。若诊断开销明显影响训练，优先减小预先固定样本量或执行频率并同步三组；不能减少正常训练实例来冒充原预算。

如果IL后反复变差，或奖励排序确实偏离精确排序，再单独设计下一轮网络学习实验。新的IL/reward对照也从同一新初始化开始，不从旧Epoch100续训。此轮三组只改变搜索算子。

## 6. 第五步：20轮结束后汇总，再决定后续

交付：

1. 三组逐epoch、逐J的固定验证与独立诊断曲线，并同时报告Epoch20和各组验证best；不只挑一个有利点。
2. Expert真实改善、上限命中率、算子接受与上界贡献、产生Expert的链步数。
3. RL后与IL后质量、梯度和参数更新结果；上界奖励选路regret。
4. 质量、Gurobi调用、训练和诊断耗时、硬件资源分配。

这一轮能比较同一平滑预算下三种算子的早期训练效果；三组都平滑减少，不能证明平滑预算优于固定30。前20轮也不能证明后期10步足够，或哪一组最终100轮最好。一个seed只能作为初筛，明确差异后再用其他seed复核。

结果支持某方案且后续不改规则时，可以从本次新训练checkpoint严格继续100轮计划，不必浪费前20轮。若要加入新的IL/reward规则并评价整套方法，应从头训练对应对照。最终配置冻结后再使用测试500、Real529及需要的旧人工5000报告。
