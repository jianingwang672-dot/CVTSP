## 1. 固定基础与实验边界

| 项目 | 固定设置 |
|---|---|
| Reference 候选 | 200 条，去重规则不变 |
| Anchor | Predictor 筛选、Gurobi 精算、严格上界构造均不变 |
| Top-K | 30：质量20＋质量受限多样性10；前60/相对5%门槛不变 |
| 主体学习 | 密集POMO＋有界精确Expert辅助RL；保留现有自适应规则 |
| IL基准 | 5遍；改进Expert权重5 |
| Replay | 30%，容量50000；本轮不同时改动 |
| 正式训练预算 | 100 epoch × 20000实例；batch64，J20–100，POMO=J |
| 正式学习率 | 初始1e-4，最小1e-5，余弦总长100，warmup1 epoch |
| 固定验证 | 已冻结2000例；单greedy＋Gurobi，Reference门槛不变 |
| 正式人工测试 | 已冻结500例；完整POMO、无增强、Gurobi精算取最优 |

新的学习率下限是实验设置，不改写旧E500实验参数和结果。现有 `e500` profile 会覆盖同名算法参数，包括学习率、move上限和IL遍数；实现新实验时必须明确处理覆盖顺序，并检查最终解析配置。不能只在启动命令追加参数就假定生效。当前专用启动脚本实际下限仍是1e-7，不应据此直接启动本方案。

测试500与Real529不用于下面的参数筛选。另建固定诊断实例；与可取得的现有验证、开发和测试实例做内容查重，保存seed、文件校验和、实例指纹。完整历史随机训练数据未保留，不能声称逐条验证了与全部历史训练数据不重叠。

## 2. 首先补充诊断记录

修改日志采集，不修改选择、接受、奖励、tie-breaking和优化器步数。每个epoch保存汇总；原始详细数据只保存诊断样本，避免巨大日志。

| 模块 | 新增记录 |
|---|---|
| 局部搜索链 | J、起点类型、初始/最终上界、接受步数、停止原因、是否达到上限 |
| 搜索算子 | swap/2-opt各自评估次数、接受次数、累计接受上界下降、候选评价耗时 |
| 最终Expert | Anchor精确值、最终精确值、相对改善、来源、额外精算次数 |
| RL/IL | 各阶段裁剪前/后梯度范数、实际参数变化量、优化器步数、耗时 |
| RL分项 | 密集/精确辅助的优势分布、辅助权重；在诊断batch额外测两项梯度范数和方向相似度 |
| 阶段评价 | epoch开始、RL结束、IL结束时，同一诊断集上的单greedy与完整POMO精确结果 |
| 效率 | 采样、Gurobi、局部搜索、RL、IL、Predictor、验证的实际墙钟耗时 |

算子累计上界下降只能归因于已接受的上界move，不能当作算子真实makespan贡献；真实贡献通过下一阶段消融比较。记录并行墙钟时间与worker累计时间的区别。

日志实现后的核验：快速语法检查、相关既有测试、固定输入下新旧路线/Expert/接受move一致性；诊断不得多做optimizer.step，不得消耗训练RNG或修改训练模式/缓存。用保存恢复RNG、独立评价环境，检查带日志和不带日志的训练更新一致。

产物：字段说明、逐epoch汇总、诊断样本明细、日志开销比较。

## 3. 局部搜索实验：先离线对比，不训练模型

### 3.1 固定输入

- 新建200例固定诊断集，J20/40/60/80/100各40，建议种子20261012。
- 使用旧E500的Epoch20、100、365三个完整checkpoint，覆盖较早、中期与后期策略状态；三个checkpoint分别分析，不能只汇总。
- 每个checkpoint在每个实例上只生成一次候选并选择一次Anchor，缓存实例、去重候选、Anchor精解、上界表、Top-30起点和模型状态标识。
- 所有搜索条件读取同一份缓存，禁止重新采样或重新挑选起点。先确认checkpoint包含对应Reference和Predictor；缺失则标记缺失，不用其他epoch状态替代。

### 3.2 五组条件

| 编号 | 算子 | 每条起点move上限 | 对照目的 |
|---|---|---:|---|
| L0 | swap＋2-opt | 30 | 当前基准 |
| L1 | swap＋2-opt | 10 | 降低上限是否节省时间且保留改善 |
| L2 | swap＋2-opt | 60 | 增加上限是否产生额外真实改善 |
| L3 | swap-only | 30 | swap单独的贡献 |
| L4 | 2-opt-only | 30 | 2-opt单独的贡献 |

L0与其余条件使用同一实例配对比较。近似评分、接受阈值、候选顺序及tie-breaking不变。

主要搜索消融先统一关闭near-miss，避免它掩盖搜索差异；这只是诊断设置，不修改正式训练的near-miss规则。对每组最佳终点，即使上界未证明改进，也额外Gurobi精算一次作为诊断，并分别报告：

1. 按正式接受规则会采用的Expert真实改善；
2. 最佳终点精算后实际改善，用于识别上界漏掉的好路线。

第二项额外精算只供分析，不回灌IL或replay。缓存相同终点的精算结果。使用相同Gurobi参数，检查最优状态；失败单独报告，不当作正常结果混入均值。初筛后，再对基准和候选方案恢复正式near-miss规则进行复核。

### 3.3 输出与决策

- 每J、每checkpoint分别报告：真实改善均值/中位数、改善实例占比、配对胜平负和改善差的95%配对bootstrap区间。
- 报告搜索链步数分布、上限命中率、两类起点贡献、每个算子的接受上界下降和墙钟耗时。
- 报告每实例收益与收益/秒；重复计时且交替条件顺序，避免缓存和机器负载造成误判。
- 优先保留质量更好或质量基本相当且明显更快的方案；质量相当的容忍幅度应在看结果前固定。小样本无法区分时扩充诊断集，不宣称等价。
- 若30步上限很少命中，且60步没有额外改善，不增加上限；若10步确实损失改善，不降低上限。具体结论必须来自结果。

产物：`local_search_summary.csv`、逐实例配对结果、运行配置与缓存manifest。

## 4. 网络学习实验：先诊断，再决定是否改IL

### 4.1 上界奖励诊断

- 另建100例固定诊断实例，每J20例，建议种子20261013；不得从正式测试500抽取。
- Epoch20、100、365上均采样一次完整Target POMO路线，用与训练一致的Anchor/Expert整路线最小上界评分。
- 所有不同Target路线均Gurobi精算，记录上界选择路线的真实排名、真实最优路线、选择regret及上界松弛。
- 额外对比混合代价优势与全精确代价优势的符号一致率；非最优精算单独处理。
- 优先复用 `scripts/diagnose_target_route_selection.py`，但先核查其模型状态恢复、数据查重和评分分支。新增汇总指标后再运行，不能将它当作已实现完整诊断。

regret定义为“上界选中路线的精确值−本次Target候选的最小精确值”，不是相对全局最优的误差。只有证明奖励排序存在明显问题，才设计新的reward改动；此阶段不直接修改RL。

### 4.2 RL之后、IL之后的阶段评价

- 用独立输出目录从同一个旧Epoch100完整状态做诊断分支，保存并恢复Target、Reference、Predictor、optimizer、scheduler、replay和RNG；不覆盖旧训练。
- 先跑3个诊断epoch，每epoch2000个新实例，保持同一训练数据序列与原scheduler连续状态。短程结果只用于机制诊断，不能当作新的正式从头训练结果。
- 在每epoch开始、全部RL结束、全部IL结束三个时点，评价上面的固定诊断100例：单greedy与完整POMO均用Gurobi精算。
- 同时记录梯度、参数变化、Target−Expert差距与IL token accuracy，判断IL是否稳定改善或削弱RL之后的路线质量。

### 4.3 有证据后才比较IL强度

若阶段诊断提示IL之后质量反复变差，再做IL 1/2/5遍三个配对短程分支：从相同完整状态开始，使用同一训练数据流，replay30%、改进Expert权重5与其他参数均不动。一个种子初筛，再用另外两个种子确认趋势；没有问题证据则先保留IL5遍。

不同时改变replay比例、样本权重或RL权重。分支从相同状态出发，不代表后续Expert、Reference和replay一直相同；这些随训练产生的差异必须记录。

产物：奖励排序诊断表、分阶段精确评测表、IL条件对照表与训练状态manifest。

## 5. 正式从头训练与最终输出

局部搜索和学习诊断结束后，记录每个改动的证据，冻结最终配置，再随机初始化训练100 epoch × 20000实例；学习率1e-4→1e-5。worker与GPU根据当时资源确认，固定并写入配置，不用更大worker数代替算法对照。

启动前核验：解析配置确实包含min-LR1e-5、选择的move/IL设置、无checkpoint加载；数据校验通过；Python/CUDA/Gurobi正常；快速相关测试通过。诊断模式关闭，常规汇总日志保留。

tmux运行，每epoch保存checkpoint，固定验证2000按原规则更新Reference和best。最终冻结checkpoint后使用人工测试500及Real529报告泛化；旧人工5000可用于与旧实验同协议比较，不用于这次调参。

若要单独证明学习率下限有效，需另做相同预算、其他配置相同的1e-7对照。若整套配置一起改变，只能报告整套方法结果，不能把收益单独归因于学习率或某个算子。

最终交付：

1. 哪些局部搜索配置保留、哪些舍弃，以及质量/耗时依据。
2. RL/IL阶段诊断与上界奖励偏差结果。
3. 最终训练配置、固定验证曲线、最佳checkpoint。
4. 每J的正式测试结果、配对改善与耗时。

只在阶段完成、异常或需要决策时汇报，不持续发送日志。
